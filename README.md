# أدوات الدراسة

منصة عربية متجاوبة للطلاب والطالبات، مبنية بـReact 18 وTypeScript وVite 6 وTailwind CSS 4 وReact Router 6. جميع الأدوات تعمل داخل المتصفح؛ لا يوجد Backend أو حساب مستخدم أو رفع للملفات.

## الأدوات

مصدر الحقيقة الوحيد للأدوات والأقسام ومساراتها هو `src/config/tools.ts`، ويحتوي أربعة أقسام وعشر أدوات:

### الملفات والصور
- `/reader` — قارئ PDF مع معاينة الصفحات والبحث والتنقل بين الصفحات.
- `/image-to-pdf` — ترتيب الصور وإنشاء مستند PDF منها.
- `/merge-pdf` — ترتيب ملفات PDF ودمجها.
- `/pdf-pages` — معاينة صفحات PDF وتحديدها وحذفها مع إمكانية التراجع.
- `/image-tools` — قص الصور وتدويرها وتغيير أبعادها وصيغتها وجودتها.

### التركيز والمذاكرة
- `/pomodoro` — مؤقت تركيز واستراحات قابل للضبط، مع سجل جلسات محلي.

### التخطيط والمواعيد
- `/exam-countdown` — إضافة الاختبارات وتعديلها وترتيبها واستيراد نسخة JSON أو تصديرها وتقويم ICS.
- `/countdowns` — عدادات للمواسم المقدّرة وإضافة مناسبات شخصية قابلة للمشاركة.
- `/schedule` — إنشاء جدول أسبوعي، كشف تعارض الأوقات، وتصديره بصيغتي PNG وPDF.

### الحاسبات
- `/calculator` — حاسبة علمية، وإحصاءات، وعمليات مصفوفات حتى 3×3.

## التشغيل والتطوير

يتطلب Node.js وnpm. اختُبر المشروع على Node.js 22.22.3 وnpm 10.9.8.

```bash
npm ci
npm run dev
```

أوامر التحقق والبناء:

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

## اختبارات المتصفح

توجد 17 حالة Playwright: فتح المسارات العشرة، واختبارات سير عمل ترفع ملفات اختبار مؤقتة وتتحقق من النتائج والتنزيلات. ثبّت Chromium واعتماديات النظام أولًا عند الحاجة:

```bash
npx playwright install --with-deps chromium
npm run test:e2e
```

في بيئة التطوير التي أُعدّ فيها هذا الإصدار تعذّر بدء Chromium بسبب غياب مكتبة النظام `libnspr4.so`؛ نجح سرد الحالات باستخدام `npm run test:e2e -- --list`، لكن لم تُنفّذ الحالات على المتصفح. لذلك لا تُعد اختبارات Playwright ناجحة حتى تُشغّل في بيئة يتوفر فيها Chromium واعتمادياته.

## النشر على Cloudflare Pages

- أمر البناء: `npm run build`
- مجلد المخرجات: `dist`
- أُضيف `public/_redirects` لتوجيه مسارات التطبيق إلى `index.html`، و`public/_headers` لترويسات الأمان والتخزين المؤقت.

إعداد PWA وملف manifest وService Worker يُنشأ أثناء البناء بواسطة `vite-plugin-pwa`. حمّل التطبيق في المتصفح مرة واحدة قبل استخدامه دون اتصال؛ تبقى بيانات المؤقتات والعدادات والجدول في IndexedDB، وتُحفظ تفضيلات الواجهة والتنقل في LocalStorage على الجهاز نفسه. لا تُرسل الملفات أو البيانات إلى خادم.

## النشر على GitHub Pages

الموقع منشور على GitHub Pages عبر `.github/workflows/deploy-pages.yml`، ويُبنى تلقائيًا عند الدفع إلى `main` أو عند تشغيل سير العمل يدويًا (`workflow_dispatch`).

- الرابط: `https://<owner>.github.io/areana-ai/` (يُشتق اسم المستودع من `GITHUB_REPOSITORY`).
- أمر البناء الخاص بالنشر: `npm run build:pages`، وهو يشغّل `npm run build` ثم ينسخ `dist/index.html` إلى `dist/404.html` حتى تصل المسارات العميقة مثل `/reader` إلى التطبيق.
- يجب بناء الموقع بمسار أساس مطابق للمستودع؛ يتولى `vite.config.ts` ذلك عند ضبط `GITHUB_PAGES=true`، ويستخدم الراوتر `import.meta.env.BASE_URL` نفسه، ولا حاجة لتعديل أي مسار يدويًا.
- تفعيل Pages مرة واحدة من إعدادات المستودع (Settings → Pages ← Build and deployment ← Source: GitHub Actions) خطوة يدوية لازمة، لأن إنشاء موقع Pages يتطلب صلاحية إدارة المستودع التي لا يملكها رمز سير العمل. بعد التفعيل يعمل كل نشر تالٍ تلقائيًا.

## الخصوصية والمعالجة المحلية

- عمليات PDF الثقيلة والصور تُنفّذ في Web Workers، وتُستخدم Canvas لمعالجة الصور.
- ملفات المستخدم تُقرأ محليًا وتبقى في المتصفح؛ لا توجد خدمة رفع أو API خارجي.
- الإعلانات معطّلة افتراضيًا (`ADS_ENABLED = false`)، ولا يظهر رابط تيليجرام حتى يُضبط عنوان حقيقي في `TELEGRAM_BOT_URL`.

## حالة التحقق والقيود المعروفة

- `npm run build`: **نجح** بعد تحديث الاعتماديات وترقية Tailwind CSS.
- `npm test`: **نجح — 6 ملفات و14 اختبارًا** لخدمات PDF والصور والحاسبة وICS وخدمات Web Worker.
- `npm run test:e2e -- --list`: **نجح — سرد 17 حالة**؛ التنفيذ الفعلي ينتظر بيئة Chromium مكتملة كما هو موضح أعلاه.
- Lighthouse: **لم يُشغّل**، لعدم توفر متصفح Chromium صالح في بيئة التنفيذ؛ لا توجد درجات أداء أو إمكانية وصول مُدّعاة.
- `npm audit`: بقي تنبيهان متوسطا الخطورة ضمن `react-router` المستخدم عبر `react-router-dom` 6. الإبقاء على الإصدار 6 شرط للمشروع، بينما يقترح التدقيق إصدارًا رئيسيًا أحدث للإصلاح. يستخدم التطبيق مسارات ثابتة محلية ولا يستخدم SSR؛ راجع `// LIMITATION:` في `src/App.tsx` وأعد تقييم الترقية إذا تغيّر شرط الإصدار.
